# 정독 우선순위

> 서지 목록은 [references/related-work.md](./references/related-work.md)에 188건이 있다 (고유 URL 기준, 2026-08-13). 전부 읽을 수는 없고 읽을 필요도 없다. 이 문서는 **어떤 문헌을 왜 읽어야 하는지**를 열린 항목 기준으로 줄 세운 것이다.
>
> 기준은 하나다: **읽으면 결정이 바뀌거나 닫히는가.** 이미 확정된 결정을 보강하는 문헌은 인용만 하고 읽지 않는다.

## 티어 1 — 구현 시작 전 정독 (열린 항목을 닫는다)

| 순위 | 문헌 | 닫는 항목 | 읽어야 하는 이유 |
|---|---|---|---|
| 1 | **Qu, Tu & Bao (2025), Is Semantic Chunking Worth the Computational Cost?** (Findings of NAACL 2025) | 열린 항목 **청킹 전략** | 결론(시맨틱 청킹은 비용 대비 이득 없음)은 알지만, **어떤 고정 길이·오버랩 설정과 비교했는지**를 알아야 우리 기본값을 정할 수 있다. 문서 40건 규모에서 그대로 쓸 수 있는 설정이 본문에 있을 가능성이 높다 |
| 2 | **Huang et al. (2024), Large Language Models Cannot Self-Correct Reasoning Yet** (ICLR 2024) | **T1 재시도 정책** (제약은 확정, 세부 미정) | "외부 피드백 없는 자기교정은 해롭다"는 제약은 이미 design.md에 박았다. 남은 질문은 **어떤 종류의 외부 신호가 유효한 피드백으로 인정되는가** — 실행 오류 메시지는 되고 자체 재검토는 안 되는 경계가 본문에 있다 |
| 3 | **Wen et al. (2025), Know Your Limits: A Survey of Abstention in LLMs** (TACL 2025) | **D6 거절 응답 스키마** | 거절을 어떤 형태로 표현할지(플래그·확신도·이유 문구)가 아직 미정이다. 서베이라 기법·평가지표가 정리되어 있어 한 편으로 설계 공간 전체를 볼 수 있다 |
| 4 | **When2Call (NAACL 2025)** — https://aclanthology.org/2025.naacl-long.174/ | **D6 거절 응답 스키마**, **R1 무매칭** | 조사 에이전트가 "거절 응답 설계에 가장 순수하게 부합"이라 지목한 벤치마크. 도구 호출 / 역질문 / 불가 인정 **세 갈래 결정**을 다루므로 우리 `ask` 응답 타입 설계에 직접 대응된다 |

**티어 1의 공통점**: 넷 다 우리가 아직 코드로 옮기지 못한 지점을 다룬다. 읽는 순서는 위 순위 그대로 — 청킹은 데이터 적재 단계에서 가장 먼저 필요하고, 거절 스키마는 도구 인터페이스를 확정할 때 필요하다.

## 티어 2 — 구현 중 참조 (정독 아니라 조회)

| 문헌 | 쓰이는 지점 |
|---|---|
| PostgreSQL: SET TRANSACTION / Client Connection Defaults / GRANT | **D4** SELECT-only를 애플리케이션 파싱이 아니라 DB 권한·트랜잭션 레벨에서 강제할 때 |
| PostgreSQL: 7.8. WITH Queries | **D5** 재귀 CTE로 그래프 탐색 구현할 때 |
| pgvector README (HNSW / IVFFlat / Iterative Index Scans 절) | 벡터 인덱스 파라미터 결정, `WHERE` 필터와 함께 쓸 때의 over-filtering 대응 |
| MCP 스펙 (이미 [정리됨](./references/mcp-spec.md)) | `outputSchema`·`structuredContent`로 구조화 응답 정의할 때, transport 결정할 때 |
| RAGAs (EACL 2024 Demo) / ARES (NAACL 2024) | **Q1** 환각 방지를 자체 엣지 세트로 검증할 때. 참조 정답 없이 faithfulness를 재는 방식이 필요해지면 |
| **Hasan et al. (2026), MCP Tool Descriptions Are Smelly!** ([related-work.md](./references/related-work.md) 5.4) | **D9** 도구 description 4개를 실제로 작성할 때. D9는 "요구 출력 형태 축으로, compact하게"까지만 정했고 실물은 아직 없다. 856개 도구 실측이라 smell 유형 목록이 본문에 있고, **설명을 과하게 보강하면 실행 스텝 +67%·일부 퇴행**이라는 경계선도 여기서 나온다 |

## 티어 3 — 논문이 아니라 환경 검증 (선행 조건)

이 항목들은 읽어서 닫히지 않는다. 직접 돌려봐야 닫힌다.

> **0순위 — 문헌보다 먼저 데이터셋을 대조한다.** 열린 항목을 닫기 전에 *"이 항목이 걸린 데이터 자산을 서로 대조했는가"*를 먼저 묻는다. 손에 있는 데이터셋이 가장 싸고 가장 결정적인 정보원이다. 방법은 [dataset-analysis.md](./dataset-analysis.md)의 재현 절 참조.

| 열린 항목 | 해야 할 일 |
|---|---|
| **MCP transport** | stdio(로컬 서브프로세스)로 충분한지, 심사 시연에 Streamable HTTP가 필요한지 판단 |
| **임베딩 모델** | **존재 확인과 메모리 실측은 닫혔다** — `bge-m3`(1.2GB·8K·1024차원) · `nomic-embed-text`(274MB·2K·768차원) 둘 다 Ollama 실물 확인, 기본값 후보는 `bge-m3`(근거는 [design.md](./design.md) 열어둔 항목). CPU 전용 실측(2026-08-18)은 bge-m3 **1.2GB** / nomic **376MB**인데 **LLM과 동시 적재하면 둘 다 4GB 하한을 넘어** 메모리로는 갈리지 않는다. 남은 것은 **적재 후 검색 품질 비교** 하나 — 40건 문서로 두 모델을 같은 질문에 걸어 본다. 배포 스키마가 `vector(768)`이라 bge-m3를 쓰면 DDL 변경이 따라온다 |
| **LLM 모델** | **닫혔다** — 블로그·공지 문면 `Gemma 4 E2B` 재확인(2026-08-14) + 레지스트리 실물 + `e2b-it-qat` 한국어 응답 확인으로 모델 **확정**. **CPU 전용 실측도 2026-08-18에 끝냈다** — `num_gpu:0`을 강제하면 **4.0GB · `100% CPU`**(GPU 적재값 1.7GB의 약 2.4배)로, 원문의 `RAM 최소 4GB`를 넘는다. **그래도 열리는 항목은 없다** — 권장 모델을 그대로 쓰기로 했고, 권장 모델과 RAM 값이 맞지 않는 것은 원문 안의 긴장이지 우리가 풀 문제가 아니다 ([design.md](./design.md) 열어둔 항목 **RAM 4GB 하한**). 실측값은 시연 환경이 4GB를 넘어야 한다는 근거로만 쓴다 |
| **T4 유사도 임계값** | 논문으로 정할 수 없다. 자체 엣지 세트로 실험해 정하되, questions.json에서 역산하지 않는다 (D7) |
| **TACC 적용 세부** | 필수 참조 [1]은 이미 [정독했다](./references/tacc-context-composition.md). 매트릭스가 탐색적 가설이므로 우리 데이터·모델로 간단히 재검증하는 실험이 남았다. 적용 지점은 반환 컨텍스트 선별 하나다 — nl2sql 스키마 선별은 테이블이 8개뿐이라 대상이 아니다. 병렬 병합·부분 응답이 반환량을 늘리므로 이 지점의 중요도가 크다 |
| **엔티티 정규화 수준** | T5 판정 전 개체명을 어디까지 정규화할지. 데이터셋 개체명이 전부 합성 패턴이라 문헌으로도 데이터로도 안 닫힌다 — 자체 엣지 세트로 정한다 |
| **그래프 적재 방식** | 그래프가 테이블에서 100% 도출되므로 `nodes`/`edges`를 별도 적재하지 않고 기존 테이블 위 **뷰**로 구성할 수 있다. "온톨로지 기반" 요구를 설명하기 쉬운 쪽과 견줘 판단 — 문헌이 아니라 스키마를 짜 보고 정한다 (design.md D5 하위) |

## 티어 4 — 인용만, 정독 불필요

이미 확정된 결정을 **보강**하는 문헌들이다. 발표·보고서에서 한 문장 인용에 쓰이고, 읽어도 구현이 바뀌지 않는다.

| 문헌 | 어디에 인용 |
|---|---|
| Shen et al., Small LLMs Are Weak Tool Learners (EMNLP 2024) | **D1** 서버 측 규칙 라우터 — 소형 LLM에게 도구 선택을 맡기지 않은 이유 |
| ToolRet (Findings of ACL 2025), MetaTool (ICLR 2024) | **D2** 도구 4개 유지 — 인벤토리가 커지면 선택이 붕괴한다 |
| 선택지 개수 정량화 문헌 — [related-work.md](./references/related-work.md) **5장 (조사 완료)** | 위와 같은 지점. Mem2ActBench의 hard/random 대조가 가장 직접적이다. **인용 전 5.5(반증 문헌)·5.7(프레이밍 리스크) 확인 필요** |
| Shi et al. (ICML 2023), Yoran et al. (ICLR 2024) | **D6** 무매칭에 병렬 폴백을 쓰지 않은 이유 |
| RULER (COLM 2024), Lost in the Middle (TACL 2024), Levy et al. (ACL 2024) | **Q2** 컨텍스트 절사 필요성 |
| All-in-One (SIGMOD 2017), Hirn & Grust (SIGMOD 2021) | **D5** RDBMS 내부 그래프 처리의 선례 |
| ISO/IEC 39075:2024 (GQL), SQL/PGQ (SIGMOD 2022) | "온톨로지 기반" 요구 대응 — 프로퍼티 그래프의 규범 근거 |
| Pylon-7 수치 (47%↓ / 37%↑ / 3.5x) | 과제 배경 서술. **저자가 "탐색적(n=5)"이라 명시했으므로 단서를 붙여 인용** |
| **[related-work.md](./references/related-work.md) 6장 (테스트 세트 생성·평가, 7건)** | **엣지 세트 생성 방법 결정에 이미 소비됐다** — CheckList의 유형 매트릭스, Nature의 꼬리 소실, EMNLP 2025의 페르소나 세분화 무이득, MT-Bench·Panickssery의 판정 편향이 각각 골격·생성 범위·카드 분량·judge 미사용을 정했다([`edge-set/`](../edge-set/README.md)). 결정이 끝났으므로 정독하지 않고 인용만 한다 |

## 이 우선순위의 근거

정독은 비용이다. 우리가 읽어야 하는 것은 **아직 정하지 못한 것을 정해주는 문헌**뿐이다.

- **티어 1**은 열린 항목을 직접 닫는다 → 읽는다.
- **티어 2**는 구현 중 필요한 값을 찾아보는 참조 문서 → 통독하지 않고 해당 절만 조회한다.
- **티어 3**은 문헌으로 닫히지 않는다 → 실행해서 닫는다. 데이터셋 대조([dataset-analysis.md](./dataset-analysis.md))와 air 검증([air-evaluation.md](./air-evaluation.md))이 문헌으로는 나오지 않았을 결론을 낸 사례다.
- **티어 4**는 이미 내린 결정의 보강재 → 인용만 한다. 여기에 정독 비용을 쓰면 결정이 하나도 닫히지 않는다.

**5장(선택지 개수 정량화, 25건)을 티어 1로 올리지 않는 이유.** 그 장의 문헌은 확정된 결정(D2·D3)을 보강하고, 원문을 읽어도 구현이 바뀌지 않는다. 인용 시 반드시 알아야 할 것들 — 5.5(반증 문헌)·5.6(인용 금지)·5.7(프레이밍 리스크) — 은 **원문이 아니라 우리 요약**이라 저장소에서 바로 읽힌다. 정독 비용이 0이므로 티어 체계의 대상이 아니고, 티어 4에 단서로만 표시한다. 예외는 위 티어 2의 Hasan et al. 하나다 — 그것만 **아직 만들지 않은 산출물**(도구 description)에 걸린다.
