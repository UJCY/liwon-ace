# 구조 엣지케이스 카탈로그

> 설계 결정 배경은 [design.md](./design.md) D6·D7 참조. (2026-07-30 그릴 세션 결과)

## 원칙 — 무엇이 허용되는 분석인가

| 레벨 | 정의 | 허용 |
|------|------|------|
| **구조 레벨** | 데이터셋 내용을 몰라도 성립하는 시스템 실패 유형. 어떤 데이터가 와도 존재하는 케이스 | ✅ 분석·설계 반영 |
| **인스턴스 레벨** | questions.json 30개 개별 질문, 문서 40건 개별 내용에 맞춘 튜닝 | ❌ 금지 (과적합) |

이 문서의 모든 케이스는 데이터셋 인스턴스를 참조하지 않는다. 케이스 서술에 특정 질문·특정 문서가 등장하면 그 케이스는 잘못 작성된 것이다.

## 카테고리 1 — 라우터 경계

| ID | 케이스 | 기대 동작 |
|----|--------|----------|
| R1 | **무매칭**: 후보 도구 없음 (스몰토크, 데이터 범위 밖 주제) | 도구 호출 없이 구조화 거절 응답 (`out_of_scope`) 반환. 에이전트는 모른다고 답변 (D6) |
| R2 | **애매 매칭**: 후보 복수, 스코어 동률·기준 미달 | 후보 도구 병렬 호출 후 병합 (D3) |
| R3 | **복수 도구 질문**: 질문이 두 영역에 걸침 (예: 정형 수치 + 문서 근거) | R2와 같은 메커니즘 — 걸친 도구들 병렬 호출·병합 |

무매칭(R1)과 애매(R2)는 다르다: 애매는 후보가 **있고** 확신이 없는 것, 무매칭은 후보 자체가 **없는** 것. 무매칭에 병렬 폴백을 쓰면 무관한 컨텍스트로 환각을 유발하므로 금지.

## 카테고리 2 — 도구 실패

| ID | 케이스 | 기대 동작 |
|----|--------|----------|
| T1 | nl2sql: LLM이 유효하지 않은 SQL 생성 | 실행 전 검증 실패 → 구조화 에러 반환. 재시도 횟수는 열린 항목 |
| T2 | nl2sql: SELECT 외 구문 생성 (INSERT/UPDATE/DDL) | 무조건 차단. 실행 금지, 에러 반환 |
| T3 | nl2sql: 실행 성공, 결과 0행 | 실패 아님 — "결과 0건"을 정상 응답으로 명시 반환 (에이전트가 "없다"고 답하도록) |
| T4 | vector_search: 전 청크 유사도 임계 미만 / 0건 | "관련 문서 없음" 응답. 저유사도 청크를 억지로 반환하지 않는다 (환각 방지) |
| T5 | knowledge_graph: 질문 개체가 그래프에 없음 | "개체 없음" 응답. 유사 이름 추측 매칭하지 않는다 |
| T6 | 공통: DB 연결 실패 등 인프라 오류 | 데이터 부재(T3~T5)와 구분되는 에러 타입으로 반환 |

공통 규약: **"데이터에 없음"과 "시스템 오류"는 다른 응답 타입**이다. 에이전트가 이 둘을 구분해 답변할 수 있어야 한다.

## 카테고리 3 — 응답 품질

| ID | 케이스 | 기대 동작 |
|----|--------|----------|
| Q1 | 에이전트가 컨텍스트에 없는 사실 생성 (환각) | 모든 `ask` 응답에 출처 메타데이터(사용 도구, 참조 데이터 식별자) 포함. 답변은 반환 컨텍스트 근거로만 생성 |
| Q2 | 도구 결과가 소형 LLM 컨텍스트 한계 초과 | TACC 선별 — 상위 N개 청크/행만 반환, 전량 투입 금지 |
| Q3 | 거절 응답(R1, T3~T5)을 받고도 LLM이 아는 척 답변 | 거절·부재 응답 수신 시 정형화된 "모름" 답변 강제 |

## 검증 정책 (D7)

| 세트 | 용도 | 규칙 |
|------|------|------|
| **자체 엣지 세트** (직접 작성) | 위 케이스 유형별 검증 | 케이스 유형 기반으로 작성. 데이터셋 인스턴스에서 역산하지 않는다 |
| **questions.json 30개** | 회귀 전용 | 규칙 튜닝에 사용 금지. 설계 변경 후 정상 케이스 30/30 유지 확인용으로만 실행 |

엣지 대응을 넣다가 정상 케이스를 깨는 것이 이 구조의 주 리스크 — 회귀 세트가 그 안전망이다.
