## 미션

KOSSA 요강 원문:

> "복잡한 설정은 그만! 규격화된 최신 기술로 **장애 지점을 줄인** 똑똑한 AI 검색 비서를 만들어라!"

블로그 표현:

> "사람이 말로 질문하면, AI가 스스로 DB를 뒤져서 정답을 찾아주는 시스템"

PostgreSQL + pgvector 위에 벡터 검색, NL2SQL, 지식 그래프를 **MCP(Model Context Protocol)** 로 통합한다. 기존 RAG 파이프라인(청킹→임베딩→인덱싱→검색→리랭킹)의 운영 복잡도를 MCP 표준으로 낮추는 것이 핵심 취지다.

요강이 비유로 든 것은 **"스마트 멀티탭 시스템"** — 맞춤형 배선(기존 파이프라인) 대신 규격화된 콘센트(MCP)에 꽂는 구조다.

### 요강이 제시한 정량 목표

> MCP 기반 파이프라인은 튜닝 없이 **64.0%의 정확도**를 달성하며, 튜닝 파라미터 **9개를 2개로**, **장애 지점을 3개에서 1개로** 줄이는 등 운영 복잡도를 극적으로 감소시켰습니다.

**주의**: 이 수치는 **MCP가 기존 RAG 파이프라인을 대체하는 맥락**이다. 우리 내부 설계(예: 라우터 배치별 실패 지점 수)에 그대로 적용하면 유추이지 문면 근거가 아니다.

## 구현해야 하는 컴포넌트 4개

1. **벡터 데이터베이스** — PostgreSQL + pgvector. 문서를 벡터 변환·저장하고 유사도 기반 의미 검색. 임베딩 적재는 참가자 직접 구현 (`document_chunks` 테이블이 빈 상태로 스키마에 포함됨).
2. **MCP 서버 (도구 3종)** — 벡터 검색, NL2SQL, 지식 그래프. "3개의 MCP 도구를 구현합니다." (블로그 문면)
3. **도구 자동 선택** — 블로그 원문: *"규칙 기반 라우터가 질문 유형을 분석하여 **적합한 도구를 자동 매칭**합니다."* ("매칭"이지 "호출"이 아님. **수는 원문이 명시하지 않는다** — 한국어 무표 명사라 단수·복수 어느 쪽으로도 읽힌다. 도구 1개라는 근거는 문면이 아니라 questions.json의 `tool`이 배열이 아닌 문자열이라는 스키마 사실이다). KOSSA 요강은 이를 "MCP Parallel 패턴"이라 부름 — 아래 주의 참조.
4. **AI 에이전트 연동** — Ollama 소형 LLM이 MCP로 도구를 호출하고 답변 생성.

**KOSSA 요강은 다르게 나눈다.** 요강의 구현 목표 문장은 *"벡터 검색, 자연어 질의(NL2SQL), 온톨로지 기반 지식 그래프, 그리고 AI 에이전트를 하나의 통합 시스템으로 구현한다"* 이고, **나열된 산출물 넷에 라우터가 없다.** 라우터는 "개발과제 예시"에만 나오며, 예시 5개 항목의 동사는 전부 참가자 행위다 (구축 · 설계 및 구현 · 선택 · 연동 · 적용). 요강 기준으로 라우터는 **만들어 낼 산출물이 아니라 넷을 "하나의 통합 시스템으로" 잇는 배선**이고, "자동"의 주어는 라우터이지 LLM이 아니다. 이 대비는 라우터 배치 판단의 재료다 ([routing-topology.md](./routing-topology.md) 3.5).

### 과제 흐름도 (블로그)

```
사용자 질문 → AI 에이전트 → 라우터 → MCP 서버 → PostgreSQL → 답변 반환
```

## 데이터셋 (companyx-dataset-v1.0)

가상 IT 솔루션 기업 Company-X의 운영 데이터 (2024-01 ~ 2026-06).

| 데이터 | 형식 | 규모 | 대응 도구 |
|--------|------|------|----------|
| 테이블 데이터 | SQL (DDL + INSERT) | 8개 테이블, 약 800행 | NL2SQL |
| 문서 데이터 | Markdown 40건 (장애보고·기술문서·회의록·제안서) | + index.json | 벡터 검색 |
| 관계 데이터 | JSON (노드 + 엣지) | 133노드, 354관계 | 지식 그래프 |
| 예시 질문 | JSON | 30개 (도구별 10개) | 라우터 자체 테스트 |

- questions.json의 도구 식별자: `nl2sql`, `vector_search`, `knowledge_graph` (각 10개, 질문당 1개).
- 그래프 노드 유형: client(30) / product(12) / employee(45) / project(40) / department(6). 관계 7종 (BELONGS_TO, HEAD_IS, USES, MANAGES_ACCOUNT, HAS_PROJECT, LEADS, REPORTED_ISSUE).

## 제약 조건

- **외부 API 사용 불가** (OpenAI, Claude 등). 모든 모델은 Ollama 로컬 실행.
- **GPU는 "선택"이다** — 권장 개발 환경 표의 `LLM 실행` 값이 두 출처 모두 `Ollama (로컬, GPU 선택)`이고, 블로그 본문은 *"GPU 없이 CPU만으로**도** 구동 가능합니다"*로 쓴다. **가능 서술이지 의무 서술이 아니다** (2026-08-18 재확인. 종전 서술 *"CPU만으로 구동 가능해야 함"*은 원문보다 강한 표현이라 정정했다).
- PostgreSQL 15+ / pgvector.
- **RAM 최소 4GB** · Linux 권장 (macOS / WSL2 가능). 단 **이 두 행은 블로그 `blog/9`의 "권장 개발 환경" 표 한 곳에만 있다** — 공지·요강에는 `RAM` 표기가 0회다. 그리고 표제가 *"권장 개발 환경"*이므로 **개발 기계 사양**이고, **심사 실행 환경의 사양을 적은 문면은 출처 3곳 어디에도 없다**(미확인). 전 항목 대조는 [dataset-analysis.md](./dataset-analysis.md) 7장.
- `air` 프레임워크(리원에이스 오픈소스, Apache-2.0)는 **권장이지 의무 아님**. https://airmcp.dev / https://docs.airmcp.dev
- LLM 권장: 블로그·공지는 "권장 개발 환경" 표에 **`Gemma 4 E2B (Ollama 로컬 실행)`**을 명시(2026-08-14 재확인, 두 출처 문면 동일), KOSSA 요강은 "온프레미스 소형 LLM(7B)"로 표기 — **차이 존속**. 공통분모는 "Ollama 로컬 소형 LLM". 문면 확인 기록은 [dataset-analysis.md](./dataset-analysis.md) 7장.
- 임베딩 권장: 공지는 *"Ollama의 임베딩 모델을 활용하여 적재"*까지만 쓰고 **모델명을 지정하지 않는다**. 블로그·요강에는 임베딩 모델 언급이 없다 (2026-08-14 재확인).

## KOSSA 요강의 추가 요구 (개발과제 예시)

요강 "개발과제 예시" 5개 항목 중 3개가 우리 설계에 직접 걸린다.

- 규칙 기반 라우터를 통한 도구 자동 선택 — **MCP Parallel 패턴**
- **온톨로지 기반** 지식 그래프
- **선택적 컨텍스트 큐레이션 (TACC 적용)** — 필수 논문 [1]의 기법: 컨텍스트를 무조건 많이 주지 말고 모델 특성·과업 유형에 따라 선별 구성

### ⚠️ "MCP Parallel 패턴"은 원문이 정의하지 않는다

출처 3곳(요강·블로그·공지)과 데이터셋을 **전수 검사**한 결과 ([dataset-analysis.md](./dataset-analysis.md) 6장):

| 출처 | "병렬" | "Parallel" |
|---|---|---|
| KOSSA 요강 | 0회 | **1회** — 위 항목의 괄호 표기 |
| 블로그 / 공지 / 데이터셋 | 0회 | 0회 |

**어느 출처도 무엇이 병렬인지 설명하지 않는다.** 유일한 출현은 "규칙 기반 라우터를 통한 도구 자동 선택"에 붙은 괄호 별칭이다. 그리고 questions.json 30개는 `tool`이 **배열이 아니라 문자열**이다(30/30, 예외 0건) — 기대 출력이 도구 1개임을 스키마가 못 박고 있다. 블로그 문면 자체는 수를 명시하지 않으므로 여기서 단수를 읽어내지 않는다.

→ **여러 도구를 동시에 호출하는 것은 과제 요구가 아니라 우리 설계 선택이다.** 우리 설계에서 병렬을 쓰는 근거는 문면이 아니라 자산 중복 실측이며, 그 결정은 [design.md](./design.md) D3에 있다. 이 문서(출처)와 그 문서(판단)를 섞지 않는다.

## 검증 기준 (과제가 제공하는 것)

- questions.json 30개로 자체 테스트: 질문별 기대 도구(`tool`)와 힌트(`hint`) 제공 → 라우터의 도구 선택 정확도 검증 가능.

**단서**: 대조 결과 30개 중 2건에 결함이 있다 — #5는 동일 구조 질문(#25·#29)과 배정이 어긋나고, #23은 데이터에 없는 개체명("서울물산")을 참조한다. 근거는 [dataset-analysis.md](./dataset-analysis.md) 5장, 회귀 기준 처리는 [design.md](./design.md) D7. **30/30은 원칙적 규칙으로 달성할 수 없다.**
