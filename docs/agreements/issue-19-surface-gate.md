# 합의 — issue #19: surface-gate.json 의 tables 를 파생으로 옮긴다

> 2026-08-27 grilling 세션의 합의. 이슈 원문은 #19, 확정 제약은 D7·D12.
> 아래 실측 수치 중 "오프라인"이라 표시한 것은 이 세션에서 캐시된 임베딩으로 계산한
> 시뮬레이션이며, 구현 시 러너로 다시 재서 그 수치를 문서에 적는다.

## 판정 — 이슈의 반증 조건이 걸렸다

**게이트는 도구 선택에 관여한다.** 이슈의 해석("오염의 여지가 작다 — 게이트는 걸렸는가만
본다")은 낱말 단위에서는 맞지만 문항 단위에서는 틀렸다. `route()` 의 게이트 히트 1비트가
R5 해소 분기(`vector_search` 강제)를 탈지 말지를 정하고, 그 분기는 도구를 반환한다.

- 실물 1 — **reg#28** (*"Product-S1 관련 고객 이슈 현황은?"*): 저작 낱말 `고객` 하나로만
  게이트에 걸린다. 이 낱말을 빼면 maxdoc 0.596 ≥ 0.52 라 `vector_search` 로 강제되고
  기대는 `knowledge_graph` 다 (오프라인).
- 실물 2 — **#17**: edge-cases.md 가 이미 *"게이트 낱말 `고객사`가 R5 해소 분기를 차단"*
  이라고 기록했다. 게이트 소속 여부가 반환 도구를 바꾼 기존 반례다.

따라서 AC2(점수가 같으면 세 번째 저작 자산으로 등재)는 **조건 불성립**, AC3(D12 서술
수정)·AC4(생성 스크립트로 이동)가 적용된다.

## 판정축 — (a)/(b)/(c) 가 아니라 저작 대 파생

이슈의 (b) "테이블명 8개만"은 두 해석 모두 퇴화한다.

- 한국어 대표형 8개로 읽으면: 게이트는 `any(w in question)` 불리언으로만 쓰이는데, 대표형
  8개의 히트 집합이 59문항(회귀 30 + 엣지 29) 전부에서 (a) 저작 21낱말과 같다 — 재 볼
  것 없이 점수 동일이 **증명**된다.
- 영어 테이블명으로 읽으면: 한국어 질문에 걸리지 않아 (c) 비움과 같다.

그래서 판정은 **(a) 저작 대 (d) 파생**으로 낸다. (a)(b)(c)(d)의 라우팅 축 실측은 AC1 을
채우는 부속 기록으로 남긴다.

## 결정 1 — `tables` 를 전면 파생으로 옮긴다

- **출처**: `companyx-dataset-v1.0/sql/01-schema.sql` 의 `-- N. 라벨` 주석. `COMMENT ON` 은
  0건이지만 이 8줄이 같은 역할이고, 이미 커밋된 파생 자산 `schema-annotated.sql` 안에
  그대로 실려 있다. erd.md 는 쓰지 않는다 — `sales` 라벨이 "매출 내역"이라 우핵 규칙이
  `매출`을 잃고 reg#1·OP-03 이 추가로 갈린다.
- **대상 테이블**: `02-data.sql` 에 INSERT 가 있는 테이블 = 정확히 8개. `column_values_ko`
  파생과 같은 입력 기준이라 `document_chunks`(참가자 적재용 빈 테이블)가 규칙 추가 없이
  자연 배제된다.
- **규칙**: 라벨에서 괄호 제거 → `/` 분해 → 조각별 마지막 어절(한국어 합성명사의 우핵).
  결과 9낱말: 계약·고객사·매출·부서·솔루션·제품·직원·티켓·프로젝트.
- **모양 유지**: `{테이블명: [표층형]}` 형태를 유지한다 (`products` → `["제품","솔루션"]`,
  나머지 1원소). `src/assets.ts` 는 이 모양을 펴서 읽으므로 TS 로더는 손대지 않는다.
- **`_provenance`**: `tables` 도 derived 로 바뀐다. surface-gate.json 은 전면 파생 자산이
  된다.

**동의어 12낱말은 지운다** — 거래처·계약서·부서장·인력·팀원·사원·상품·과제·판매·영업·
문의·지원요청 (사원은 `column_values_ko` 에 있어 어휘로는 산다). 59문항 어디에도 안
걸린다(실측). 근거는 4.3 의 선례와 같다 — 어느 세트에도 안 걸리는 어휘(`그리고` 등)를
지웠던 것과 일관되고, 효과를 잴 수 없는 보험을 저작 자산으로 유지하지 않는다.

**정직한 대가 (문서에 한정 서술로 적는다)**: 동작 보존은 측정 세트 59문항 위에서의
증명이지 전칭이 아니다. 심사 새 질문이 지워진 동의어로만 오고 개체 한정어가 없으면,
종전에는 게이트 히트 → argmax 로 가던 것이 maxdoc 판정(구제 또는 거절)으로 넘어간다.
D17 서열로는 답이 거절로 바뀔 수 있는 방향이다.

## 결정 2 — `route()` 구조를 바꾼다: R5 해소를 거절 직전 구제로

```
route(question):
  if 게이트 미히트 and 개체 한정어 없음:
      if maxdoc ≥ 임계  →  vector_search     # 거절 직전 구제 (R5)
      else              →  out_of_scope      # 거절 (R1)
  →  시그니처 임베딩 argmax                    # 도구 선택
```

`harness/build/router.py` 와 `src/router.ts` 를 같은 구조로 고친다.

- **논거 (점수와 독립)**: R5 구제의 명분은 "스키마 어휘 없는 문서 질문을 거절하지 않기"
  였다. 거절 직전이 이 분기의 원래 자리다. 게이트 히트 1비트가 도구를 직접 반환하는
  경로가 사라지고, 게이트는 문자 그대로 거절 판단에만 관여하게 된다 — D12 서술이
  구조적으로 참이 된다.
- **실측 (오프라인)**: 파생 9낱말 × 새 구조는 저작 21낱말 × 현행 구조와 **59문항 전부에서
  반환 도구·상태가 같다** (회귀 26/30 · 엣지 22/29). reg#28 하락이 사라진다. `route()`
  반환이 같으므로 e2e 병렬 승격의 입력도 같다.
- **기각한 변형**: maxdoc 을 전역 우선으로 두는 재배열 — 회귀 21/30 로 무너진다. R5 구제를
  게이트 히트 문항까지 확대하는 것은 명분에도 어긋난다.
- **임계 유효성 (오프라인)**: 새 구조에서 임계가 실제로 판정하는 문항은 게이트 미히트 ·
  개체 없음 16건뿐이고, 0.46~0.57 에서 점수 동일. 거절군 maxdoc 최대 0.457 / 구제군 최소
  0.573 으로 간격이 깨끗하다. `model.json` 의 평탄 구간 주석은 유효하다.

**노출 기록 (6절 한계에 적는다)**: 구조 후보 3개와 파싱 규칙 후보 3개를 세트 점수로
대조해서 골랐다. 채택 근거는 동작 보존 증명과 위의 독립 논거이지만, 고르는 순간 점수를
본 것은 사실이다 — 임계 0.52·병렬 짝 선택 규칙과 같은 종류의 노출이다.
