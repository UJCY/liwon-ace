# 필수 참조 [2] — Pylon-7: AI 에이전트 워크플로 7계층 참조 모델

> Jeon, H. (전현우, Codepedia Labs) (2026-02).
> "Pylon-7: A 7-Layer Reference Model for AI Agent Workflows — Exploratory Study on MCP Layering for Efficiency, Accuracy, and Safety in Commodity Hardware Environments"
> https://zenodo.org/records/18808598 · 블로그의 **47%↓ 토큰 / 37%↑ 정확도 / 3.5x 비용 효율 수치의 원 출처**.

## 한 줄 요약

MCP의 핵심 가치는 "확장"이 아니라 **"구조화 + 제약"** — 적절한 수준의 구조화·제약(L3)이 토큰 절감과 정확도 향상을 **동시에** 달성하며, 잘 설계된 MCP를 가진 소형 모델이 MCP 없는 큰 모델을 이긴다.

## 두 가지 축 (혼동 주의)

**① Pylon-7 계층** — OSI 모방한 에이전트 워크플로 7계층 참조 모델:

| 계층 | 이름 | 역할 | 비용/위험 |
|------|------|------|----------|
| L7 | Interface | 사용자 접점 (챗 UI) | 최소 |
| L6 | Analysis | 입력 파싱, 의도 분석, 계획 | 낮음 |
| L5 | Routing | 작업 분기 결정 | 낮음 |
| L4 | Service | 외부 서비스/API/검색 호출 | 중간 |
| L3 | Resource | 파일·코드 읽기, 리소스 접근 | 중간 |
| L2 | Mutation | 코드 수정, 리팩토링 | 높음 |
| L1 | System | 셸 실행, 루트 권한 | 최대 |

원칙 3개: **하강 비용 원칙**(아래 계층일수록 토큰·위험 증가), **게이트웨이 원칙**(MCP는 특정 계층에 속하지 않고 계층 간 전이를 표준화하는 게이트웨이), **독립 원칙**(각 계층 독립 동작).

**② MCP Level (L0~L4)** — 실험 변수인 MCP 활용 깊이 (위 계층과 별개):

| Level | 이름 | 내용 |
|-------|------|------|
| L0 | No MCP | 원시 데이터 직접 제공 |
| L1 | Basic Tool | 도구 이름 + 결과 텍스트 |
| L2 | LSP Jump | 심볼 수준 요약이 전체 코드 대체 |
| L3 | Structured | 구조화 출력 + KB 검색 + **후보 액션 제시** |
| L4 | Whitelist | L3 + 위험 액션 차단 |

## 실험

Qwen 2.5 7B + GPT-OSS 20B, Ollama CPU 전용, 인프라 운영 10개 시나리오 × 5레벨, 총 615회(메인 465 + ablation 150). 블로그의 "Pylon-7 465회"는 메인 실행 수.

## 핵심 결과

1. **L0→L3: 토큰 47% 감소 + 정확도 37% 향상 동시 달성** (7B, p=0.0001, d=0.925). 비용과 품질이 트레이드오프가 아님.
2. **L3가 스위트스팟**: L4는 L3 대비 정확도 차이 없음(p=0.594) — 추가 제약은 안전 이득만. 정확도 최적=L3, 안전 최적=L4.
3. **7B+L3 > 20B+L0**: 728토큰/0.936 vs 2,534토큰/0.792 — 3.5배 저렴하고 14.4%p 정확. **L3 이상에선 모델 크기보다 MCP 구조가 지배적** (양 모델 0.93+).
4. **어려운 과업엔 MCP가 필수**: 자동 조치(S08) 0→1.00, AI 판단(S09) 0.30→1.00. "후보 액션 제시 + 근거 제공"이 결정적.
5. **L2.5 ablation — 반직관 결과**: KB 검색만 추가하면 오히려 정확도 하락 (0.735→0.551, 10개 중 6개 시나리오에서 악화). 후보 액션 단독(0.503)도 호출 계층 단독(0.366)도 L3(0.735)에 못 미침 — **컴포넌트 시너지**가 핵심. 과업 유형에 맞는 컨텍스트 매칭 필요 (→ TACC 논문의 출발점).
6. **3단계 결정 파이프라인 검증**: Stage A(결정적 규칙 필터) → Stage B(AI 교정) → Stage C(전체 AI 분석). 규칙이 명확한 케이스를 먼저 거르고 AI는 좁혀진 후보만 판단 — 단일 AI 호출보다 비용·정확도 모두 우위.

## 실무 가이드라인 (논문 6.2)

단순 과업엔 MCP는 토큰 절감용 / 복잡 판단엔 L3 적용 / 안전 중요 환경엔 L4 / **모델 키우기 전에 MCP부터 개선** / MCP의 "닫는" 능력 활용 / 컨텍스트는 양이 아니라 과업 유형으로 큐레이션.

## 한계 (논문 명시)

n=5 탐색적, 시나리오 5/10 천장 효과, 평가 함수 시나리오별 상이, 모델 일반화(Gemma 등) 미검증.

## 우리 설계에 주는 시사점

| 논문 발견 | 우리 설계 연결 |
|----------|--------------|
| 게이트웨이 원칙 | 라우터 배치 A안(게이트웨이형)이 이 명명과 대응 — 배치 자체는 미확정이며 비교 재료로 쓴다 ([routing-topology.md](../routing-topology.md) 3.6) |
| Stage A 규칙 필터 | 규칙 기반 라우터(D1·D3) = Stage A. 무매칭 거절(D6)도 "규칙이 먼저 거른다"의 구현 |
| L3 = 구조화 출력 + 후보 제시 | 도구 응답을 자유 텍스트가 아닌 **구조화 형식 + 출처 메타데이터**로 (Q1 대응). MCP 스펙의 `structuredContent`/`outputSchema` 사용 근거 |
| L4 = 화이트리스트 | D4 SELECT-only 강제 = L4 패턴. "닫는 설계"가 심사 포인트 |
| 7B+MCP > 20B, L3 이상 모델 크기 무관 | 소형 Gemma 4 E2B로 충분하다는 과제 전제의 근거. 모델 업그레이드보다 도구 응답 구조화에 투자 |
| KB 단독 추가는 해로움 | 라우터가 병렬 병합(D3) 시 결과를 전부 합치지 말 것 — 유형에 맞는 결과 우선, 나머지는 절사 (Q2·TACC 연결) |

**주의**: 수치(47%/37%/3.5x)는 저자 스스로 "탐색적(n=5)"이라 명시 — 우리 문서·발표에서 인용할 때 "탐색적 연구 결과" 단서를 붙이는 것이 정확하다.
