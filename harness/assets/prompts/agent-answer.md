# 에이전트 최종 답변 프롬프트

도구가 돌려준 구조화 응답을 받아 사용자에게 답할 때 쓴다.
`status` 가 `partial` · `out_of_scope` · `entity_not_found` 인 경우가 이 프롬프트의 존재 이유다
([design.md](../../../docs/design.md) D10, [edge-cases.md](../../../docs/edge-cases.md) Q1·Q3).

```
아래는 사내 검색 시스템이 돌려준 결과다. 사용자 질문에 한국어로 답하라.

[질문]
{{QUESTION}}

[검색 결과]
{{STRUCTURED_RESULT}}

[답변 규칙]
- 검색 결과에 없는 사실을 만들지 마라.
- status가 partial이면: 요구된 답이 없다는 것을 먼저 말하고, adjacent_facts는
  "다만 이런 기록은 있습니다"로 분리하라. adjacent_facts를 요구된 답인 것처럼 말하지 마라.
- status가 out_of_scope면: 답할 수 없다고만 말하라. 수치나 사실을 추측하지 마라.
- status가 entity_not_found면: 그 이름을 찾을 수 없다고 말하라. near_names를 답으로 쓰지 마라.
- 3문장 이내.

[출력 형식] 아래를 그대로 따른다. 문장으로 풀어쓰지 마라.
답변가능: 예 | 아니오        ← 요구된 답이 검색 결과에 있으면 '예', 없으면 '아니오'
확인된 답: <내용 또는 없음>
인접 사실: <내용 또는 없음>

예시)
답변가능: 아니오
확인된 답: 없음
인접 사실: 해당 고객사가 이슈를 보고한 기록은 있습니다.
```

## 첫 줄이 열거형인 이유

**채점 가능성 때문이다.** 자유 서술만 받으면 환각 여부를 결정적으로 판정할 수 없다 —
모델은 형식은 지키면서도 `없음` 대신 *"…확인되지 않습니다"* 로 쓴다.
`답변가능: 예|아니오` 한 줄을 먼저 뱉게 하면 그 줄만으로 채점이 끝나고,
`edge-set/README.md` 의 "LLM 판정자를 쓰지 않는다" 방침이 답변 축에서도 유지된다.
